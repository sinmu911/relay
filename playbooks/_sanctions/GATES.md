# 검증 이중 구조 — 형식 게이트 vs 진위 게이트

| | 형식·추적 게이트 (자동) | 진위 게이트 (사람·비서실장) |
|---|---|---|
| 장치 | `.claude/hooks/claim_gate.py` (Stop 훅) | 스킬 `verify-node-reports`, `report-review-before-approve` (Mac) / `report-verified` |
| 보는 것 | 도구 실행 有, `근거:` 줄 有, 근거 토큰(명령·파일·개수·exit·해시)이 이번 턴 실제 출력에 존재, `미확인:` 有 | 그 출력이 주장과 **관련 있고 맞는지**, 원자료(로그·파일·화면) 대조 |
| 못 보는 것 | 실제 출력을 엉뚱한 주장에 갖다 붙인 경우 | — (사람 시간이 듦) |
| 통과 의미 | "검증 가능한 형태로 보고됨" | "사실로 승인됨" |

규칙
- claim_gate 통과 ≠ 정상. 사용자에게 "정상"으로 전달·승인하는 것은 진위 게이트를 거친 뒤에만.
- 상한 도달 단계: 1~max_blocks회 전체 요구 → 이후 2회는 `미확인:`만 강제(최소 제약) → 그 뒤 강제 통과 + 화면 경고 + 다음 요청 첫 줄 공개 + `~/.claude/claim_gate_escapes.jsonl` 영구 기록.
- 에스컬레이션: 최근 7일 강제 통과가 `node_policy.json`의 `escalate_after`(기본 2) 이상인 노드는 세션 시작 때 알림 → 비서실장이 원자료 대조, 결과를 `LEDGER.md`에 1줄 + 장치 1개.
- 완전 자동 진위 검증은 불가능하다고 인정한다. 자동 게이트는 사람 검증의 비용을 줄이는 도구다.
