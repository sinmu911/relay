## 4. 장치별 동작

### claim_gate (Stop 훅) — 보고 차단
응답에 정상·완료·확인·통과 같은 주장이 있으면 아래를 모두 요구한다. 한국어와 영어 주장을 모두 검사한다.
1. 이번 턴에 실제 도구 실행이 있었다.
2. `근거:` 줄이 있다. 그 줄에서 뽑은 토큰(`백틱` 명령, 파일, `6/6` 같은 개수, exit 코드, 커밋 해시)이 **이번 턴 실제 도구 입력·출력에 그대로 있다.**
   - "근거: 됐음"은 추적할 토큰이 없어서 차단된다.
   - 출력이 6/6인데 근거에 9/9를 쓰거나, 가짜 exit 1을 쓰면 차단된다.
3. `미확인:` 진술이 있다. 확인 못 한 것이 없으면 "미확인: 없음"이라고 쓴다.

상한에 도달했을 때의 단계(조용한 통과는 없다):
- `max_blocks`회까지: 위 조건을 전부 요구한다.
- 그 뒤 2회: 근거 요구만 풀고 `미확인:`은 계속 강제한다.
- 그 뒤: 강제 통과한다. 대신 사용자 화면에 경고(systemMessage)를 띄우고, 다음 요청 첫 줄에 "직전 보고 미검증"을 공개하게 하고, `~/.claude/claim_gate_escapes.jsonl`에 영구 기록한다.

에스컬레이션: 최근 7일에 강제 통과가 `escalate_after`(기본 2)회 이상인 노드가 있으면, 세션 시작 때 `[에스컬레이션]` 알림이 뜬다. 그러면 비서실장이 원자료와 대조한다.

노드별 강도 (`node_policy.json`): 노드는 `CLAUDE_NODE` 환경변수로 먼저 판별하고, 없으면 `cwd_prefix`로 판별한다.

| 노드 | max_blocks | min_traced |
|---|---|---|
| default | 3 | 1 |
| chatbot | 1 | 2 |
| secretary | 3 | 1 |

### 스킬 자동 사용
- 각 SKILL.md에 `name`, `description`, `metadata.triggers` frontmatter를 넣었다. Claude Code는 description을 보고 스킬을 자동으로 호출한다.
  - 이전에는 매뉴얼이 `playbooks/`에만 있어서 **자동 발견이 안 됐다.** 오늘 찾아서 고쳤다.
- `sync_skills.py`가 `.claude/skills/`에 링크를 건다. 원본은 하나뿐이고, 링크라서 수정이 즉시 반영된다.
  - `--target ~/.claude/skills`로 실행하면 그 컴퓨터의 모든 세션이 이 스킬을 본다.
- 실제 세션에서 작동을 확인했다. 세션 시작 알림과 요청 라우팅(`relay-shell-release`, `report-verified`)이 이 세션에서 실제로 발동했다.

### merge_gate (PreToolUse 훅) — 병합 승인 경로
- "병합해" 한 마디로는 병합되지 않는다. 사용자의 가장 최근 메시지에 정확히 `병합 승인 #2`가 있어야 그 PR만 병합된다.
- main에 직접 푸시하려면 `main 푸시 승인` 문구가 필요하다. 작업 브랜치 푸시는 이 훅과 무관하다.
- CI `checks`가 같은 검사를 GitHub에서 독립적으로 실행한다. 실행한 세션의 자기 보고와 분리된 검증이다.

### install_approved.py — 공급망 위험 차단
- 자동 git pull은 만들지 않았다.
- origin/main에 병합된 커밋만 설치한다. diff를 보여준 뒤 `--approve <커밋>`을 받아야 `~/.claude/relay-approved/<커밋>`에 스냅샷으로 설치하고 `current` 링크를 바꾼다.
- 훅은 승인된 스냅샷에서 실행된다. 그래서 작업 폴더가 바뀌어도 실행되는 코드는 그대로다. 시험에서 작업 폴더에 악성 줄을 넣어도 실행본에는 0줄이었다.

### 앱 변경 — 아이콘 v2 통일
- `app.html`(화면 아이콘)과 `sw.js`(알림 아이콘)를 `icon-192.png`에서 `icon-192-v2.png`로 바꿨다.
- 구/신 파일은 바이트까지 같다(md5 `1c21a0dc…`). 그래서 그림이 바뀌는 게 아니라, 폰이 새 이름으로 다시 받아 옛 캐시 아이콘을 교체하는 효과다.
- Mac 노드에서는 같은 수정을 로컬 커밋(`d9c3448`)까지 했지만 GitHub 푸시 인증이 없어 실패했다(exit 128). 그래서 클라우드 세션에서 다시 적용해 푸시했다.

## 6. 한계와 미확인

- **진위는 검증하지 못한다.** claim_gate는 근거 토큰이 실제 출력에 있는지까지만 본다. 실제로 있는 출력을 엉뚱한 주장에 갖다 붙이는 경우는 못 잡는다. 그래서 진위 게이트는 비서실장이 맡는다(`GATES.md`).
- skill_router는 단어 일치 방식이라 오탐·미탐 여지가 남아 있다.
- 미확인:
  - 강제 통과 때 `systemMessage` 화면 경고가 실제로 표시되는지
  - 폰 설치 앱 아이콘과 알림 아이콘이 실제로 교체되는지 (main 병합과 Pages 배포 후에 확인 가능)
  - GitHub Pages가 어느 브랜치를 배포하는지 (이 환경에서 Pages 주소 접속 불가)
  - Mac 노드에 적용된 상태와 사본 버전
  - `node_policy.json`의 노드별 `cwd_prefix` (비어 있음)
- 노드 보고 중 확인하지 못한 것: Mac의 git 사용자 설정 완료 보고 ("이서준"). 이 저장소 쪽에는 근거가 없다.
