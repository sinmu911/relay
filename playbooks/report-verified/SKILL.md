# report-verified

> 출처: 비서실장 세션의 guestcard-report-verified 5규칙(2026-10-31)을 모든 노드·모든 "정상" 보고용으로 일반화.
> 하객카드 전용 절차(헤드리스 크롬 재현·기록 삭제·rep_notify 원복)는 Mac의 원본 스킬이 마스터. 여기는 공용 골격.

## 목적
어떤 노드든 "정상/완료/확인"을 보고하기 전에, 확인한 범위와 못 한 범위를 증거로 가른다.

## 언제 쓰는지
- "정상이야?", "됐어?", "확인해봐", "보고해", "고쳤어?" 에 답할 때
- 다른 노드(세션)의 보고를 받아 사용자에게 전달·승인할 때
- 사용자가 "이상하다"고 할 때

## 입력
- 확인 대상 — 사용자 메시지에 적힌 기능/화면/파일
- 일별 검사 스크립트 — 매뉴얼의 `files/check.py` (예: `playbooks/relay-shell-release/files/check.py`), 하객카드는 Mac의 `~/MicLab/common/guestcard_check.py`
- 다른 노드 보고 — 원문 그대로. 원자료(로그·파일·출력)와 대조 전에는 사실로 취급하지 않는다

## 순서
1. 무엇을 "정상"이라 부를지 범위를 먼저 적는다: 서버 / 코드 / 사용자 폰 화면.
2. 해당 검사 스크립트를 돌린다. 스크립트가 없으면 만들지, 수동 확인으로 둘지 정하고 보고에 적는다.
3. 사용자 화면 동작이면 같은 조건으로 재현한다(실제 기기 조건·라이브 주소). 재현 못 하면 사용자 화면은 미확인.
4. 시험 중 생긴 흔적(기록·알림·상태)을 지우고, 지운 것도 적는다.
5. 아래 양식으로 보고한다. Stop 훅(`.claude/hooks/claim_gate.py`)이 양식 누락을 막는다.

## 결정
- 서버/스크립트만 확인했으면 → "서버 정상"까지만 쓴다. "폰에서 정상"은 쓰지 않는다.
- 다른 노드가 "정상"이라 했지만 원자료가 없으면 → "노드 보고만 있음(미확인)"으로 전달한다.
- 사용자가 "이상하다"고 하면 → 반박하지 않고 재현·로그 대조부터 한다.
- 같은 거짓 보고가 생기면 → `playbooks/_sanctions/LEDGER.md`에 1줄 + 장치 1개(스킬·훅·스크립트)를 추가한다.

## 완료의 정의
- [ ] 보고에 `근거:` 줄이 있고, 실제 실행한 명령과 그 출력/종료코드가 들어 있다
- [ ] 보고에 `미확인:` 줄이 있다 (없으면 `미확인: 없음`)
- [ ] "정상" 단어는 근거가 있는 범위에만 붙어 있다
- [ ] 이번 턴에 도구 실행이 1회 이상 있다 (claim_gate 훅이 검사)
- [ ] `python3 playbooks/report-verified/files/test_claim_gate.py` 통과
